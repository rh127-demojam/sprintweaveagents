# SprintWeave Setup Wizard

Guide the user through configuring `context/team-config.yaml` interactively. Ask structured questions, validate choices, and write the final config.

## When to Activate

- User says "setup", "configure", "customize for my team", "onboard"
- User opens SprintWeave for the first time and has default team-config values
- User says "change my team settings" or "update team config"

## Process

### Step 1: Check Current Config

Read `context/team-config.yaml`. If it has non-default values (team name != "My Team"), ask:
> "You already have a configuration for [team name]. Want to update it or start fresh?"

### Step 2: Ask Questions (Use AskQuestion Tool)

Ask these in order. Skip any the user already answered in their prompt.

#### Q1: Team Identity
```
- Team name? (free text)
- Domain? telecom | cloud | platform | generic
- Team size? (number)
```

#### Q2: Agile Framework
```
- Framework? scrum | safe | kanban | scrumban
- Sprint length? 1 | 2 | 3 | 4 weeks
- Average velocity? (story points per sprint)
```

#### Q3: Estimation & Priority
```
- Estimation scale? fibonacci (1,2,3,5,8,13) | tshirt (S,M,L,XL) | hours | none
- Priority scheme? high-med-low | moscow (Must/Should/Could/Won't) | p1-p5
```

#### Q4: Team Personas
```
- Who uses the systems you build for? (multi-select or free text)
  Suggestions based on domain:
    telecom: System Administrator, Network Engineer, NOC Operator, Platform Engineer
    cloud: DevOps Engineer, Cloud Architect, SRE, Developer
    platform: Platform Engineer, Developer, Site Reliability Engineer
    generic: Administrator, Developer, End User, Operator
- Additional custom personas? (free text, comma-separated)
```

#### Q5: Stakeholders
```
- Key stakeholders for reports/approvals? (multi-select or free text)
  Common: Product Owner, Engineering Manager, Scrum Master, CTO, VP Engineering
```

#### Q6: Technology Stack
```
- Core technologies? (free text, comma-separated)
  Examples: Kubernetes, Python, Java, REST APIs, PostgreSQL, React, Terraform
```

#### Q7: Infrastructure
```
- Monitoring stack? Prometheus/Grafana | Datadog | CloudWatch | New Relic | custom
- Cloud provider? aws | azure | gcp | on-premise | hybrid
```

#### Q8: Governance
```
- Compliance framework? ISO27001 | SOC2 | GDPR | HIPAA | internal-policy | none
- Change approval process? CAB | team-lead | auto-approve | peer-review
```

#### Q9: Documentation
```
- Default documentation audience? end-users | administrators | developers | mixed
```

#### Q10: Quality Thresholds
```
- Max story points before recommending split? (default: 8)
- Minimum acceptance criteria per story? (default: 2)
```

### Step 3: Generate Config

Build the YAML from answers. Use this template:

```yaml
# SprintWeave Team Configuration
# Generated by SprintWeave Setup Wizard
# Re-run: Type "setup SprintWeave" in chat

team:
  name: "{team_name}"
  domain: {domain}
  size: {team_size}

framework: {framework}

estimation:
  scale: {scale}
  sprint_length_weeks: {sprint_weeks}
  velocity_sp: {velocity}

priority:
  scheme: {priority_scheme}

personas:
{personas_yaml}

stakeholders:
{stakeholders_yaml}

tech_stack:
{tech_stack_yaml}

infrastructure:
  monitoring_stack: "{monitoring}"
  cloud_provider: "{cloud}"

compliance:
  framework: "{compliance_framework}"
  change_approval: "{change_approval}"

documentation:
  default_audience: "{audience}"

quality:
  max_story_points: {max_sp}
  min_acceptance_criteria: {min_ac}
  require_source_citation: true

output:
  default_format: markdown
  include_estimation: true
  include_epic_grouping: true
```

### Step 4: Write & Confirm

1. Show the generated config to the user in a code block
2. Ask: "Does this look right? I can adjust any setting."
3. On approval, write to `context/team-config.yaml`
4. Confirm: "Team config saved. All agents will now use these settings."

### Step 5: Domain Glossary Check

Based on the domain selection, verify the corresponding glossary file exists:
- `telecom` → `context/glossary.yaml`
- `cloud` → `context/glossary-cloud.yaml`
- `platform` → `context/glossary-platform.yaml`
- `generic` → `context/glossary-generic.yaml`

If missing, inform the user they can add custom terms later.

## Quick Mode

If user provides details upfront (e.g., "Setup for a cloud team of 5 using SAFe with Jira"), extract all available info and only ask for missing fields.

## Security Notes

- **No credentials in config** — If user provides API keys, passwords, or tokens, refuse to write them into team-config.yaml. Warn: "team-config.yaml is committed to git — never store secrets here."
- **Sanitize team name** — Strip any YAML special characters or multi-line content from free-text inputs before writing
- **No external references** — Config values must be plain strings/numbers. Never write YAML anchors (`&`, `*`), `!include`, or `!!python/object` tags

## Rules

- Always show the final config before writing
- Never overwrite without confirmation
- Use AskQuestion for multi-choice fields when available
- Suggest domain-appropriate defaults (don't make user guess)
- Keep the conversation concise — don't explain what each field does unless asked
